# Testbench 生成标准

## 生成前分析

先从规格、RTL 和接口定义提取验证需求，再编写 testbench。至少记录：

- DUT 参数、时钟、复位极性与同步方式。
- 每个接口的方向、位宽、握手条件及 `valid/ready/last/user/keep` 语义。
- 数据变换、延迟、吞吐、顺序、丢弃、错误响应和复位行为。
- 行号、帧号的来源、起始值、递增条件和复位条件。

规格没有定义的行为标记为未定义，不要把当前 DUT 实现自动当成规格。

## 覆盖矩阵

建立 testcase、场景、激励、预期结果、检查点和执行结果之间的映射。至少检查以下类别，并根据 DUT 特性扩展：

- 正常：最小、典型、最大长度；连续流；间隔流；单帧；多帧；背靠背帧；各种合法 `keep/user/last` 组合。
- 流控：无背压、周期背压、随机背压、长时间背压、输入空闲、输入与输出同时停顿。
- 边界：零值、全一、符号边界、计数器回绕、首拍、末拍、单拍帧、跨行和跨帧边界。
- 复位：上电复位、空闲时复位、传输中复位、背压时复位、复位释放后的首个事务。
- 异常：非法或不一致的 `keep/last/user`、截断帧、超长帧、协议稳定性破坏、超时以及规格定义的错误输入。
- 组合：参数边界、异常与背压叠加、复位与传输叠加、多接口并发及可重复随机序列。

只有在覆盖矩阵中的全部适用项都有 testcase 和自动检查后，才能声称覆盖了全部正常与异常场景。对不适用、无法激励或规格未定义的项说明原因。

## 独立参考模型

- 使用 `always_comb`、`function automatic` 或连续赋值实现功能变换，产生期望数据和协议字段。
- 参考模型只读取 testbench 激励、参数和独立参考状态，不读取 DUT 输出或层次化内部信号。
- 不实例化第二份 DUT，不调用 DUT 私有实现，不逐行复制 DUT RTL；按功能规格采用不同结构实现，避免与 DUT 共享同一缺陷。
- 无状态 DUT 全部使用组合参考逻辑。有状态 DUT 独立维护参考状态，但使用组合逻辑计算期望输出和下一状态，并在有效时钟事件更新状态。
- 对流水 DUT，将期望事务连同帧号、行号、beat 编号和预期周期信息放入队列，由 scoreboard 在输出握手时取出比较。
- 对允许可变延迟或乱序的 DUT，按事务 ID、标签或规格定义的匹配键比较，不假设固定周期。

## Scoreboard 与检查

- 仅在协议定义的采样点接收事务，通常是 `valid && ready`。
- 比较数据以及 `valid/last/user/keep` 等全部有意义的侧带字段；使用四态严格比较，避免 `X/Z` 被误判为相等。
- 检查事务丢失、重复、乱序、意外输出、期望队列残留、输出超时和协议稳定性。
- 不匹配时同时打印 expected、actual、接口名、case 名、阶段、帧号、行号、beat 编号和队列深度。
- 错误可以累计以便一次仿真暴露多个问题，但最终必须以明确的失败状态结束。

## Monitor 与日志

monitor 只能观察，不得驱动 DUT。统一记录以下事件：

- 复位进入和退出。
- testcase、帧、行的开始和结束。
- 输入与输出的每次有效握手。
- 背压开始、持续和结束。
- 参考结果入队、实际结果出队和每次比较结果。
- 协议错误、数据错误、队列异常、超时和最终统计。

每条关键日志至少包含以下字段：

```text
[time][case][stage][interface][frame][line][beat] valid= ready= last= user= keep= expected= actual= status=
```

- `time` 使用 `$time`；设置明确的 `timescale` 或 `timeunit/timeprecision`。
- `stage` 使用稳定名称，例如 RESET、DRIVE、INPUT、REFERENCE、OUTPUT、COMPARE、TIMEOUT、SUMMARY。
- `frame/line/beat` 根据协议在有效握手时更新。不要仅根据 `valid` 更新，也不要默认 `last` 或 `user` 的含义。
- DUT 没有某个标准字段时打印 `N/A`。多路接口必须打印可唯一定位的接口名或方向。
- case 开始时打印 testcase 名和随机种子；失败日志打印足够信息以定位首个错误，不依赖波形才能理解基本原因。

## 完成条件

testbench 只有同时满足以下条件才算完成：

- 覆盖矩阵全部适用项均已执行并自动检查。
- 参考模型与 DUT 独立，scoreboard 没有残留期望事务。
- monitor 和日志包含规定字段，行号与帧号更新符合协议。
- 每个 testcase 有明确结果，最终汇总计数自洽。
- 编译、仿真和 WLF 生成成功，且任何检查失败都会使整体仿真失败。
